Power — before anything else

  • V+ is the servo rail. Its own 5–6 V supply. Never from the Arduino.
  • Common ground. Co-processor, expanders, servo supply and the droid's Arduino all share 0 V.
  • Budget per servo moving, not per servo installed: ~1 A small, 2–3 A MG996R-class.
  • 1000–4700 µF electrolytic across V+/GND at the board. Not optional on a multi-servo droid.
  • ESP32 is 3.3 V logic. The PCA9685 reads 3.3 V as a valid high. Power the board from 5 V and never feed 5 V back into an ESP32 pin.
Two servos fine, three judder and stall

That is V+ sag, not protocol. The stack is not the limit: the wire carries 3 bytes per update at 115200 with 4× headroom even with 32 moving, and the PCA9685 generates all 16 PWMs in hardware.

Aggravated by speed 0 / accel 0 — which means unlimited, so every "open" is one full-jump write and a full-torque lunge, with the inrush of every servo stacking at the same instant. Give the channels real numbers: speed 80 / accel 10 is a proven start.

Multimeter on V+ during a three-servo open settles it.

Order of work

  1. Power up as above. Grounds joined.
  2. Flash PCA_Bridge (bench sketch). Plug in over USB.
  3. Simulator ▸ Setup ▸ Servo setup ▸ Open the servo setup tool ▸ Channels ▸ Connect hardware.
  4. Tick the pins in use. Name each. test to identify the panel.
  5. Per channel: dial to shut → Set MIN; dial to open → Set MAX; set speed and accel.
  6. Map each channel to the part it drives (dome map is quickest).
  7. Finish → export the config file. Keep it with the build notes.
  8. Build routines ▸ put them on slots 0–7 ▸ export sequences.h.
  9. Flash MaestroReplacement (droid sketch) with that header.

Diagnostic order — most decisive first

  1. Is the board receiving? Watch channel 0's Target box on Control Center's Status tab while the Arduino sends setTarget. That is the board's own register: independent of servo power, the servo, the linkage and the script. Moves ⇒ the byte arrived. Every other test is ambiguous.
  2. Is it power? Multimeter on V+ during a multi-servo move.
  3. Is it the address? Read the scan line the sketch prints at boot.
  4. Is it the pin? Measure at the board's own RX pad, never at the Arduino end.
  5. Loopback. Maestro TX→RX in USB Dual Port mode, or Mega pin 18→19.

Silent failures — each looks like "nothing works"

What you seeWhat it is
Serial chopped mid-sentence, one corrupt byte, then nothing DY-SV5W dropped Serial to 9600. DY::Player defaults to Serial; begin() calls Serial.begin(9600). Reads as a hang inside player.begin(). Watch at 9600, or put the player on another port.
Not one byte, no clue anywhere Stock Padawan Usb.Init() fails to a bare while(1); with the print commented out. Bad USB Host Shield halts in setup(); loop() never runs.
Freshly reset Maestro ignores its RX pin It boots in USB Dual Port, which ignores RX by design. Any test before Serial Settings are applied is meaningless.
Wire on the Mini Maestro's third serial pin does nothing TXIN — daisy-chain input, used only in USB Chained mode, dead in UART mode. Indistinguishable from a dead board.
Yellow LED double-flashing Normal. "At least one servo enabled or output driven high." Single flash = none enabled. Status, not fault.
5 V at the Arduino pin whether connected or not Rules out a short, nothing else. A broken wire and an internally open input are identical from that side.
A write moves every servo on the droid All Call 0x70. Every PCA9685 answers it out of the box, so a naive scan finds a phantom board that is really all of them. 0x71–0x73 are the subaddresses.
Channels die until you reconnect A deep sag reset the PCA9685 — prescaler lost, outputs stop. Reconnecting re-sends the clock config and a full sync. Power problem.
Channel 70 moves the servo on channel 6 Old bridge firmware reads 6 bits, not 7: 70 & 0x3F = 6. Re-flash to unlock channels 32 and up.
Dial keeps turning, panel stops moving (Maestro) Silent clamp to a stored limit — no error, no reply. Reads exactly like a binding linkage. Fix in Control Center; the simulator's read-back names it.

Maestro RX loopback — no Arduino needed

  1. Serial Settings → USB Dual Port → Apply. The TTL Port's COM port is then wired straight through to the physical RX/TX pins.
  2. Jumper the Maestro's own TX to its own RX.
  3. Open the TTL Port (not the Command Port) at 9600 in Pololu's Serial Transmitter; send a byte.

Returns ⇒ RX alive. Nothing ⇒ RX dead. Run a known-good board first as a control.
