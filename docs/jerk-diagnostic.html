Is it the clock, or is it the board?

A bench diagnostic for “it felt a little jerky”. Twenty minutes, one servo minimum.

Two different things can make a PCA9685 rig look rough, and they have different fixes. This tells you which one you have — by comparing, not by remembering, because motion is very hard to judge from memory.

suspectwhat it issignature
The clock The browser drove a fixed-rate engine from the animation frame, delivering 1, 2, 2, 1, 2, 2 engine steps per frame. Fixed in v1.31.1. Roughly equal at every speed. Present over the USB bridge, absent from sequences.h on the co-processor.
The board A PCA9685 at 50 Hz resolves 20000 ÷ 4096 = 4.88 µs. One engine step at speed 10 is 2.5 µs — half a count. Much worse at low speeds. Identical over the bridge and on the co-processor. Improves when you raise the servo frequency.

Before you start

The throw is deliberately small — 1200 to 1800 µs, ±300 µs from centre. This project knows nothing about your linkages, so check by hand that each horn you connect can travel that far without touching anything. If one cannot, unplug it and use a bare servo on the bench instead: this test is about smoothness, not about your droid.
Save your Studio project first. Loading this one replaces it — Save project in the header, then Load project to come back.

What is in it

Six channels, all with the same endpoints so the throws are directly comparable, each with a different speed. Speed is per channel, not per frame, so the ladder is side by side rather than one after another — you compare them in the same glance instead of from memory.

Step by step

0 · Before anything is plugged in. Check the PCA Studio version in the header reads v0.12.1 or later — the clock fix is in 1.31.1 / 0.12.1, and running this on an older build tests the wrong thing. Then press Save project and keep the file: Load project in step 2 replaces everything you have.

1 · Wire it. Servos on board 0, pins 0–5, in order — pin 0 is the slow one and does most of the work. Fewer is fine: with one servo use pin 0 and skip to slot 1. Give the servos their own supply with the ground commoned to the board; six servos moving together is real current, and a sagging rail looks exactly like the fault we are chasing.

2 · Load it. Load project → pca-jerk-test.pcastudio.json. You should get six channels named spd 5 through spd 40 +accel, and four slots in the sequencer strip.

3 · Connect. ⚡ Connect hardware and pick the port with the PCA_Bridge sketch on it. The chip beside the button should read hardware. If it says monitor only, that port is a co-processor and Studio is refusing to stream binary at a text console — right call, wrong port.

4 · Prove it is alive. Press all home. Everything should step to centre. Nothing moving? Fix that before reading anything into what follows. Esc is stop-everything and it works at any point.

5 · Watch slot 1 — the crawl. Select slot 1, press ▶ play slot, and watch pin 0 for the full 4.8-second travel. This is the single most revealing run in the set. See the coaching below before you judge it.

6 · Watch slot 0 — the ladder. Slot 0, play. All six move together. The question is not "is it smooth" but "are the slow ones worse than the fast ones" — that comparison is the whole diagnostic, and it is why they run together rather than one after another.

7 · Slot 3 — listen. Twenty seconds parked at centre. Put your ear near the servos. Noise while stationary is neither suspect: that is supply, ground, or a tired servo.

8 · Now the decisive half. Flash pca-jerk-test-sequences.h onto the MaestroPCA co-processor, disconnect Studio, and run slots 1 and 0 from the board itself. Same rig, same numbers, nothing but the driver changed. If the board is smooth where the bridge was rough, it was the clock. If they are identical, it never was.

9 · Optional, and worth it. Setup wizard → step 2 → change the servo pulse rate to 200 Hz, re-flash, run slot 1 again. If the crawl cleans up, you have just watched the PCA9685's resolution improve from 4.88 µs to 1.22 µs. Digital servos usually take it; analogue ones usually do not, so if anything gets hot, buzzes or will not hold, go back to 50.

How to actually look at it. Judging smoothness by eye is harder than it sounds, and the trick is amplification, not concentration. Tape a drinking straw or a lolly stick to the horn so the tip swings 200 mm instead of 20 — the same stepping becomes ten times more visible. Watch the tip against a fixed background, an edge or a ruler, not the servo body. Then compare, never judge in isolation: run the same slot twice in a row before deciding, because the second viewing is always more honest than the first.

The two comparisons that actually decide it

  1. Bridge vs co-processor. Run slots 0 and 1 from PCA Studio over USB. Then flash pca-jerk-test-sequences.h onto the MaestroPCA co-processor and run the same two slots from the board. Same rig, same numbers, different driver.
  2. 50 Hz vs 200 Hz. In the setup wizard, step 2, change the servo pulse rate and re-flash. Resolution is one period ÷ 4096, so 50 Hz = 4.88 µs, 100 Hz = 2.44 µs, 200 Hz = 1.22 µs. Most digital servos take 200 Hz happily; analogue ones usually will not — if a servo gets hot, buzzes or refuses to hold, drop back to 50.

Slow channels step, fast ones are smooth — and it is the same on the co-processor

That is the board. Raise the servo frequency, or use higher speed values with acceleration to shape the move instead of a low speed to slow it. Nothing in the software will fix 4.88 µs.

All speeds equally rough over USB, clean from the co-processor

That was the clock, and v1.31.1 fixes it. If you are still seeing it, you are on an older build — check the version in the header.

Rough on both, at every speed, and channel 5 with acceleration is no better

Neither suspect. Look at the supply: measure the rail at the servo while it moves, not at the bench PSU. Then the ground between board and supply. Then the oscillator trim on the PCA9685 — the nominal 25 MHz is often out by a few percent, which shows up as timing that is subtly wrong everywhere at once.

It is quiet moving but buzzes while holding

Not the engine at all. Try sleep when idle on that channel — it stops pulsing once the servo has settled, which is silent, cool and draws nothing. Only for parts that rest in place on their own.

Worth writing down

For each run: which channels looked rough, at what speed, and whether it changed between bridge and co-processor, and between 50 Hz and 200 Hz. Those four answers between them name the cause without any more guessing.
